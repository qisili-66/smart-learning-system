# learning.md

> 目的：沉淀本项目开发过程中的 bug 复盘、踩坑记录、错误用法、反直觉结论和优化建议。这里记录的是当前仓库可见事实与后续开发应避免的问题。

## bug 复盘

### 15. 学生测评不应被后台题库库存卡住

- 现象：学生发起测评时依赖后台题库匹配学科、难度和知识点；题库缺题或题型覆盖不足时，答题页会提示需要管理员补题，无法形成实时测评体验。
- 新口径：学生端测评按年级、学科、知识范围和难度调用 AI Agent 实时生成本次专用试卷题；生成题保存到 `question_bank` 并用内部测评标记绑定 `assessmentId`，详情和提交时读取同一批题，避免刷新变题。
- 保留能力：管理员题库录入、CSV 导入、后台题库维护和评分要点配置继续保留；后台题库作为教学沉淀、人工审核、演示数据和历史兼容来源，不作为学生新建测评的硬前置。
- 兜底策略：AI 服务不可用或返回无效题目时，后端会生成基础可提交题，避免页面空白；题量按测评模式控制在约 8-18 题，降低实时生成超长 JSON 失败风险。
- 验证点：创建测评请求包含 `gradeLevel` 后，答题页应出现 AI 生成题和卷面分区；后台 `/admin/questions` 仍可录入和管理题库；AI 生成题的内部标记不应展示给学生。

### 12. 语音转文字缺少错误提示，英语识别语言固定为中文

- 现象：学生端语音答疑点击录音后，浏览器语音识别失败时页面没有明确原因；选择英语学科时仍使用 `zh-CN` 识别，英文提问容易识别为空或识别错误。
- 根因：`frontend/src/views/student/qa/index.vue` 只处理了 `onresult` 和 `onend`，没有处理 `SpeechRecognition.onerror` / `onnomatch`；识别语言写死为 `zh-CN`，没有按学科切换。
- 当前修复：新增 `speechError` 可见提示、浏览器不支持/权限拒绝/网络失败/未检测到语音等错误文案；发送语音前要求必须有识别文本或手动修正文案；英语学科使用 `en-US`，其他学科使用 `zh-CN`。
- 验证点：拒绝麦克风权限或浏览器语音服务不可用时，页面应提示可手动输入文本；英语语音提问应走 `en-US`，中文学科仍走 `zh-CN`。

### 13. 初中题库种子不像试卷，英语题不是英文题

- 现象：旧版九科题库中英语题大量是“关于一般现在时的理解”这类中文知识点判断题，不像初中英语试卷；九科题量也偏少。
- 根因：旧版题库生成逻辑对所有学科套用同一套知识点说明模板，没有针对英语、阅读、写作、材料分析、解答题等试卷题型设计。
- 当前修复：生成器改为每科 240 题、共 2160 题；非英语学科按选择题、填空题、多选题、解答题/材料分析题生成；英语题改为英文题干和英文选项，覆盖选择、完成句子、阅读与语言运用、简答和写作。
- 当前口径：按用户要求，九科演示题库导入前直接删除旧题并重新插入新版 2160 道标准试卷风格题；由于外键为 `ON DELETE CASCADE`，旧题关联的演示答题/错题记录会随旧题清理。
- 验证点：SQL 中应有 2160 条 `VALUES` 行；英语题至少 240 条包含 `Question` 英文题干；不得再出现旧模板 `关于一般现在时的理解`。

### 14. 测评不应只是题库抽题列表，应按标准机考试卷结构生成

- 现象：原测评答题页按通用题型列表展示，后端只按固定题数抽题，不能体现语文 120 分、数学 23 题、英语听说 + 笔试等真实机考卷面结构。
- 当前修复：`AssessmentController` 增加九科 `PaperSectionSpec` 规则，按学科生成题量、板块、分值和说明；答题页按 `paperSectionTitle` 分组显示，每题显示 `maxScore`，提交时使用试卷真实总分。
- 后续方向：Agent 生成试卷应以这些卷面规则为约束，输入学科和知识点后生成对应板块题目；题库只作为兜底、缓存和人工审核来源。

### 11. IntelliJ 直接启动后端时 MySQL 使用空密码连接失败

- 现象：后端启动成功后，`PersonalDataExportCleanupTask` 定时任务第一次访问数据库时报 `Access denied for user 'root'@'localhost' (using password: NO)`。
- 根因：`docs/wiki.md` 和 `docs/Memory.md` 记录的本地默认数据库账号密码是 `root/root`，但 `backend/src/main/resources/application.yml` 实际写成了 `password: ${DB_PASSWORD:}`，IntelliJ 直接运行时未设置环境变量，就会用空密码连接 MySQL。
- 当前修复：后端配置改为 `password: ${DB_PASSWORD:root}`，README 默认值同步为 `root`，本地开发表现与项目记忆保持一致；服务器部署仍必须显式设置 `DB_PASSWORD` 覆盖默认值。
- 验证点：未设置 `DB_PASSWORD` 时，配置检查不应再出现空密码默认值；若本机 MySQL 密码不是 `root`，应在 IntelliJ Run Configuration 或终端中显式设置 `DB_PASSWORD`。
- 经验：看到 `using password: NO` 时，优先检查 Spring 环境变量默认值，而不是先怀疑业务代码或定时任务。

### 1. 中文编码显示异常

- 现象：`README.md`、`docs` 旧文档、`application.yml` 注释、部分 Java 注释和前端文案在当前 PowerShell 输出中显示为乱码。
- 影响：文档可读性下降；如果源码字符串本身已损坏，前端页面、接口提示和 Knife4j 文档也会显示异常。
- 当前判断：不能只凭终端输出断定所有文件损坏；但 `docs` 旧版内容已经明显不可读，需要重新生成干净 UTF-8 版本。
- 处理建议：先修 Markdown 和用户可见文案；源码修复要分模块、小批量、可编译验证。

### 2. 个人数据导出接口曾为空实现，现已补齐 ZIP 导出

- 原现象：`PersonalDataController.export()` 返回 `Map.of("downloadUrl", "")`，前端拿不到真实文件。
- 当前修复：已新增个人数据 ZIP 导出，汇总用户画像、学习计划、任务、学习记录、错题、测评、答疑摘要，ZIP 内含 `personal-data.json` 与 `personal-data.md`。
- 安全增强：导出时写入 `personal_data_export_log`；下载 URL 使用短期 token，数据库只保存 SHA-256 hash；链接有效期 24 小时，最多成功下载 3 次。
- 过期清理：生成新导出时会清理过期文件；后台 `PersonalDataExportCleanupTask` 每小时清理一次过期导出。
- 验证点：导出文件不能包含其他用户数据；下载必须校验当前用户、token、过期时间和次数；审计日志中不能保存明文 token。

### 3. 个人数据清空不能只删几个主表

- 原风险：只清空学习计划、学习记录、错题和测评会留下答疑会话、答疑消息、画像修正日志、学习任务、错题复习计划、测评答案和本地文件，用户会误以为个人学习痕迹已全部删除。
- 当前修复：清空入口改为服务层编排，要求密码和 `confirmText` 二次确认，删除范围明确覆盖答疑、画像修正、任务数据和相关导出/音频文件，并将删除计数写入 `personal_data_clear_log`。
- 事务边界：数据库删除与审计写入使用 `@Transactional(rollbackFor = Exception.class)`；文件删除不是数据库事务资源，若之后追求强一致性，应改为事务提交后文件清理或增加失败补偿。
- 验证点：密码错误或确认文本错误不得删除任何数据；清空成功后审计记录必须保留；重复清空应返回 0 计数而不是报错。

### 4. 学习进度报告和提醒曾偏占位，现已补齐

- 原现象：`/study-records/progress-report` 只返回空 `summary`；`/study-records/reminders` 返回空列表。
- 当前修复：已新增 `StudyProgressService`，从 `study_record`、`study_task`、`assessment`、`wrong_question` 和 `wrong_question_review_plan` 聚合学习时长、任务完成率、测评趋势、错题原因和提醒。
- 前端入口：学习首页展示本周进度报告和学习提醒。
- 后续增强：如要支持提醒已读、站内信、推送或历史追踪，应新增独立提醒表，而不是只靠实时规则生成。

### 5. 语音答疑容易被误解为完整 ASR

- 现象：AI 服务 `/qa/voice` 接收语音文件，但关键输入仍是前端传入的 `recognizedText` 或 `correctedText`。
- 影响：若文档写成“后端已内置离线 ASR”，会和实际实现不一致。
- 正确表述：当前是“前端浏览器语音识别 + 用户修正 + 后端/AI 服务答疑承接”。
- 后续优化：如要满足普通话 ASR 目标，应接入独立 ASR 模型或第三方语音识别服务。

### 6. AI 服务不可用时必须有后端兜底

- 现象：`AiService` 在调用超时或失败时会返回不可用信息；学习计划路径生成已有规则兜底迹象。
- 经验：学习系统不能把 AI 当作唯一执行路径，尤其是计划生成、主观题评分、答疑等核心功能。
- 验证点：关闭 AI 服务后，后端应返回可解释错误或规则兜底，不应 500 崩溃。

### 7. 前端 auth store 重复

- 现象：仓库同时存在 `frontend/src/store/auth.js` 和 `frontend/src/stores/auth.js`。
- 当前事实：路由守卫导入 `@/store/auth`。
- 风险：后续开发若混用两个 store，会出现登录态不同步、角色判断错乱、token 清理不一致。
- 修复方向：保留一个权威 store，迁移所有引用后删除或废弃另一个。

### 8. 学习路径生成需要按学科收敛

- 原现象：创建政治/道德与法治学习方案时，接口会把用户全局薄弱点直接传给 AI 和兜底路径；如果近期薄弱点主要来自数学，生成内容就会串到函数、方程、几何等数学知识点。
- 当前修复：`StudyPlanServiceImpl` 在生成目标计划时先按当前计划学科和目标描述过滤薄弱点；若没有匹配薄弱点，则使用目标描述或“{学科}基础知识”兜底。
- 关联修复：通用资源推荐入口没有完整计划对象时，只按传入学科过滤薄弱点，避免复用目标计划过滤逻辑时引用不存在的计划上下文。
- 体验收敛：AI 返回步骤会按诊断、练习、错题复盘、阶段测评、资源学习的优先顺序压缩，最多保留 4 个核心步骤；若 AI 返回步骤与当前学科完全不匹配，则改用后端规则兜底路径。
- 验证点：选择政治/道德与法治时，不应出现函数、方程、几何等数学知识点；路径首屏不应被长列表淹没。
- 回归覆盖：`StudyPlanFinishTaskBehaviorTests` 增加政治计划过滤数学步骤、兜底路径最多 4 步且不含跨学科知识点的测试。
- 本次验证：已运行 `backend/.\mvnw.cmd test`，后端 12 个测试全部通过。

### 9. 测评组卷需要避免连续重复题

- 原现象：生成同学科、同难度试卷时，后端按固定排序截取题库候选，连续测评容易拿到同一批题，且候选列表自身重复时会直接进入试卷。
- 当前修复：`AssessmentController` 组卷先按题目 ID/题干去重，再避开最近 5 次同学科已提交测评中用过的题；若题库数量不足，则回退到去重后的全题池，保证测评仍能生成。
- 一致性要求：详情页展示题目和提交时批改题目共用同一套稳定选择逻辑，并按 `assessmentId` 做稳定轮转，避免刷新/提交时题目顺序漂移。
- 验证点：连续创建同学科测评时，应优先出现最近未做过的题；题库不足时可以复用旧题，但同一张试卷内不应重复。
- 回归覆盖：`AssessmentSubmitBehaviorTests` 增加详情接口组卷测试，验证候选题去重并在新题足够时排除最近已做题。
- 本次验证：已运行 `backend/.\mvnw.cmd test`，测评组卷相关测试与完整后端测试均通过。

### 10. 学习资源不能使用 example.com 占位链接

- 原现象：学生端打开“一次函数基础讲义”等演示资源时跳到 `https://example.com/smart-learning/demo/...`，页面只显示 Example Domain，用户会误以为资源打不开。
- 当前修复：统一演示数据中的 3 条数学资源已改为国家中小学智慧教育平台具体搜索入口，并加入 `UPDATE` 语句修正已经导入旧数据库的 `example.com` 链接。

- 后端防线：`LearningResourceController` 返回学生端资源列表、搜索结果和详情前，以及 `StudyPlanServiceImpl` 返回学习计划推荐资源前，都会把 `example.com` 等占位资源地址替换为“初中 + 学科 + 知识点”的国家中小学智慧教育平台搜索页。

- 回归覆盖：`LearningResourceControllerTests` 验证学生端资源列表返回前会把 `example.com` 占位链接替换为官方平台搜索页。

## 踩坑记录

- PowerShell 对中文路径或中文内容的显示可能出现问号或乱码；读取 `.docx` 时可通过 Python 枚举目录 + 解析 OOXML，避免在脚本里硬写中文路径。
- Word 文档中的需求是目标，不等于当前实现。写 wiki 或验收说明时必须标注实现状态。
- Spring Security 的 `hasRole("STUDENT")` 匹配 `ROLE_STUDENT`，不要把数据库角色数字直接传给 `hasRole`。
- 当前后端上下文路径是 `/api`，但 Controller 注解中不写 `/api`；写 API 文档时要区分 Controller 路径和完整访问路径。
- 数据库初始化脚本里可能含幂等增量块，改表时要考虑老库升级，不能只改 `CREATE TABLE`。
- 高风险删除接口必须显式写清“清空范围”和“保留范围”；否则后续前端和文档很容易把部分删除误解成合规清空。
- `Redis` 出现在依赖和配置中不代表业务缓存已落地；要看具体 Service 是否使用。
- `接口返回 200` 不等于功能完成；空 `downloadUrl`、空 `reminders`、空 `summary` 这类占位返回都属于可调用但未闭环。

## 错误用法

- 错误：在文档中写“系统已支持 AES-256 加密存储”。
  正确：当前代码确认有 BCrypt 密码和 JWT 鉴权；AES-256 存储仍是需求目标/待实现。
- 错误：在 Controller 里直接写复杂推荐算法、评分算法或多表编排。
  正确：Controller 保持薄，复杂逻辑移入 Service，并增加测试。
- 错误：个人数据清空只做密码校验，然后分散在 Controller 里逐表删除。
  正确：使用服务层事务封装、二次确认、删除计数、审计记录，并明确文件清理的一致性边界。
- 错误：前端页面直接请求硬编码 URL。
  正确：统一走 `frontend/src/api/**` 封装。
- 错误：AI 结果直接覆盖用户画像或测评分数。
  正确：AI 结果应带置信度、解释和人工复核/兜底路径。
- 错误：把用户上传文件原名直接作为存储文件名。
  正确：使用 UUID 或安全文件名，原始名称只作为元数据保存。
- 错误：为了展示效果伪造接口数据并写成后端已实现。
  正确：如果是 mock 或占位，必须在 Memory/wiki 中标明。

## 反直觉结论

- “AI Agent 项目”不代表所有模块都必须由 AI 决策。很多闭环能力更适合先用规则兜底，再接入 AI 优化。
- “JWT 无状态”不等于没有服务端安全责任。个人数据清空、导出、管理端操作仍需要严格鉴权和审计。
- “需求说明写了 100% 覆盖”不等于当前项目已满足验收；验收指标需要压测、安全测试、兼容性测试支撑。
- “语音文件上传成功”不等于 ASR 成功；当前关键输入是识别后的文本。
- “有管理端页面”不等于运维能力完成；真实日志、故障、自检、备份、告警都需要验证。

## 优化建议

- 优先继续补齐 F5 进度监控；F9 个人数据导出与清空已具备基础能力，后续重点是前端审计展示、管理员审计入口和更细粒度的数据安全策略。
- 增加 API 契约测试，覆盖前端已封装的 `studentApi` 和 `adminApi` 路径。
- 给 AI 服务调用增加统一降级策略、耗时记录、模型名记录和错误分类。
- 将常量枚举集中化，例如错题原因、资源类型、题型、计划状态，避免前后端散落魔法数字。
- 学习画像应从测评、错题、学习记录中形成明确计算口径，不宜只存静态分数。
- 资源推荐可先基于知识点、学科、资源类型、难度做可解释排序，再逐步引入向量检索或模型推荐。
- 完善数据安全：敏感字段识别、导出审计、清空二次确认、HTTPS 部署说明、日志脱敏。
- 给 README 和 docs 建立 UTF-8 编码检查，避免中文文档继续损坏。

## 2026-07-18 复盘：AI 可观测性与编码风险

- AI 观测字段要在调用边界统一补齐，业务层只判断结构化字段，不应通过解析错误文案判断是否降级。
- 主观题 AI fallback 分数只能作为临时参考分，必须进入人工复核；否则低质量模型输出会污染测评分数、错题收集和画像刷新。
- 日志不能记录题干、学生答案、历史对话或导出 token；排查问题依靠 operation、endpoint、latencyMs、provider、model、failureCategory、errorCode。
- PowerShell `Set-Content` 在含中文源码文件上有编码风险，尤其会引入 BOM 或改变非 ASCII 字符串字节；修 Java/Python 源码优先使用 `apply_patch`，必要时只做极小范围且验证编译。
- 对 AI 服务做测试时，不要只测成功响应；必须覆盖空 body、缺 code、业务 500、网络异常和模型 JSON 解析失败。
