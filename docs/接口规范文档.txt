
1. 概述
1.1 编写目的
统一前后端、AI模块的接口开发标准，规范接口命名、参数格式、响应结构、鉴权规则，降低联调成本，保障代码一致性，作为全项目接口开发与评审的唯一依据。
1.2 适用范围
本规范适用于本项目所有后端RESTful接口、前端接口调用、AI模块对外服务接口。

2. RESTful 设计原则
2.1 URL 命名规范
1. 全部使用小写英文字母，多单词使用半角横杠 - 分隔，禁止驼峰、下划线
2. 路径使用名词表示资源，禁止在URL中出现动词
3. 层级不超过3级，按「业务模块/资源集合/资源ID」分层
4. 全局统一前缀：/api，文档中的接口路径均基于该前缀
示例：
✅ 正确：GET /api/wrong-questions # 获取错题列表
✅ 正确：POST /api/assessments # 创建测评
❌ 错误：GET /api/getWrongQuestion # 出现动词、驼峰命名
❌ 错误：POST /api/answerQuestion # 动词开头
plaintext
2.2 HTTP 方法约定
方法	用途	幂等性
GET	查询、获取资源数据	是
POST	新增资源、提交操作（如答疑、提交试卷）	否
PUT	全量更新资源	是
DELETE	删除资源	是
2.3 版本控制
● 当前阶段统一使用 /api 作为后端上下文路径
● 后续如需不兼容升级，再引入 /api/v2 等版本前缀，旧版本保留至少1个迭代周期

3. 统一响应格式
所有接口必须返回统一JSON结构，禁止自定义返回格式。
3.1 通用响应结构
{
  "code": 200,
  "message": "操作成功",
  "data": null,
  "timestamp": 1719820000000
}
表格
字段	类型	说明
code	int	业务状态码，详见 3.2
message	string	状态描述，成功返回 "操作成功"，失败返回具体错误原因
data	object/array/null	响应业务数据，无数据时返回 null
timestamp	long	服务器时间戳（毫秒）
3.2 业务状态码规范
表格
code	含义	场景说明
200	成功	请求正常处理完成
400	参数错误	请求参数校验失败、格式非法
401	未授权	Token 无效、过期、未携带
403	无权限	账号角色不允许访问该接口
404	资源不存在	请求的 ID 不存在、路径错误
409	业务冲突	数据重复、状态不允许操作
500	服务器内部错误	程序异常、服务故障
3.3 分页响应结构
分页查询接口的 data 固定为以下结构：
json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "list": [],
    "total": 128,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 13
  },
  "timestamp": 1719820000000
}
4. 请求参数规范
4.1 参数传递方式
表格
参数类型	传递方式	适用场景
资源 ID	路径参数 /xxx/{id}	查询单条、修改、删除
查询条件	查询参数（Query）	列表查询、筛选、分页
新增 / 修改数据	请求体（Body JSON）	表单提交、数据新增更新
4.2 分页查询规范
所有列表查询接口统一使用以下分页参数：
表格
参数名	类型	必填	默认值	说明
pageNum	int	否	1	页码，从 1 开始
pageSize	int	否	10	每页条数，最大不超过 100
4.3 参数校验规则
后端必须对所有入参做合法性校验，非法参数直接返回 400
字符串需校验长度、格式；数字需校验范围；ID 类参数需校验是否存在
校验错误的 message 需明确指出哪个参数有误，如 "用户名不能为空"
5. 鉴权与安全规范
5.1 鉴权方式
采用 JWT 令牌鉴权机制：
登录成功后返回 token 字符串
所有需鉴权接口，请求头必须携带：
plaintext
Authorization: Bearer {token}
Token 过期或无效时，返回 401 状态码，前端统一跳转登录页
5.2 接口权限分级
表格
权限等级	说明	示例接口
公开接口	无需登录即可访问	用户登录、注册、公开资源
学生权限	学生角色可访问	个人错题、学习计划、答疑
管理员权限	仅管理员可访问	资源管理、题库管理、系统监控
5.3 安全约束
全接口使用 HTTPS 传输
敏感信息（密码、手机号）禁止明文返回
防 SQL 注入、XSS 攻击，后端统一做参数过滤
单用户接口限流，防止恶意刷接口
6. 接口文档约定
所有接口必须编写文档，包含：接口描述、请求方式、路径、权限、入参、出参、示例
接口变更必须同步更新文档，禁止代码与文档不一致
新增接口需在团队内评审通过后方可开发
6.1 接口实时更新规则
每次新增、删除、重命名或调整接口字段时，必须同步更新 `docs/接口文档.txt`
文档只记录当前代码中已实现或明确标注为“暂未实现”的接口，禁止把未实现接口写成可用接口
接口响应结构发生变化时，必须同步更新响应参数说明和示例
数据库脚本变化时，必须在文档或工作日志中写明脚本路径和执行方式
7. 异常处理规则
所有异常必须被后端统一捕获，禁止直接抛出堆栈给前端
业务异常返回对应状态码与清晰的错误提示
系统异常返回 500，日志中记录完整堆栈信息，前端展示 "系统繁忙，请稍后再试"
